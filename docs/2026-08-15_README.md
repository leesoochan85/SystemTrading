# 2. 한경 컨센서스 리포트 연동

## 2.1 기존 문제

처음에는 아래 한경 내부 API를 사용했다.

```text
https://markets.hankyung.com/api/consensus/search/report
```

하지만 실제 실행 시:

```text
403 Client Error: Forbidden
```

이 발생했다.

따라서 내부 API 방식은 제거했다.

---

## 2.2 변경 방식

현재는 공개 리포트 상세 페이지를 사용한다.

```text
https://markets.hankyung.com/consensus/view/{report_id}
```

예:

```text
https://markets.hankyung.com/consensus/view/651534
```

테스트 결과:

```text
report_id: 651534
종목코드: 071050
제목: 상반기 순이익 1.9조원
URL: https://markets.hankyung.com/consensus/view/651534
```

공개 페이지 접근 자체는 정상 동작하는 것을 확인했다.

---

## 2.3 리포트 검사 주기

기존 10분 주기에서 **30분 주기**로 변경했다.

`StrategyManager.py`

```python
self.value_report_check_interval = 1800
```

즉:

```text
1800초 = 30분
```

한경 리포트를 1초마다 조회하는 구조가 아니다.

### 동작 흐름

```text
StrategyManager 실행
    ↓
30분 경과 여부 확인
    ↓
ValueQualityStrategy 실제 보유종목 확인
    ↓
새로운 한경 리포트 ID만 조회
    ↓
보유종목 코드와 일치하면 Telegram 전송
```

## 2.4 마지막 확인 리포트 ID 저장

매번 과거 리포트를 처음부터 조회하지 않도록
`value_quality.db`에 마지막 확인 ID를 저장한다.

추가 상태:

```text
value_report_scan_state
```

예:

```text
마지막 확인 ID: 651715
        ↓
30분 후
        ↓
651716 이후부터 확인
```

따라서 매 검사마다 과거 전체 데이터를 반복 조회하지 않는다.

---

## 2.5 파서 수정

초기 파서에서 리포트 발표일 대신
한경 사이트 footer의 날짜를 잘못 읽는 문제가 있었다.

잘못된 예:

```text
발표일: 20091123
```

원인은 footer의:

```text
등록(발행)일자: 2009.11.23
```

을 리포트 발표일로 잘못 인식했기 때문이다.

현재는 아무 날짜나 잡지 않고,
명시적인 리포트 관련 필드가 있을 때만 읽도록 수정했다.

따라서 현재 테스트에서는:

```text
발표일:
```

처럼 값이 없으면 빈칸으로 남긴다.

잘못된 날짜를 임의로 넣는 것보다 이 방식이 안전하다.

# 3. 실시간 FID 최소화

## 3.1 기존 구조

기존 실시간 등록 FID:

```text
체결시간
현재가
시가
고가
저가
누적거래량
(최우선)매도호가
(최우선)매수호가
```

총 8개였다.

특히 `HighBreakoutStrategy`가 event-driven 공통 등록의 registrar 역할을 하면서
이 8개 FID가 공통 종목에 적용되고 있었다.

또 `Kiwoom.py`의 실시간 콜백에서도 매 틱마다 위 값을 각각
`GetCommRealData`로 읽고 있었다.

---

## 3.2 전략별 실제 필요 FID 재정리

### HighBreakoutStrategy

실제 필요한 값:

```text
현재가
누적거래량
(최우선)매수호가
```

사용 목적:

```text
현재가
→ 신고가 돌파 / 손절 / MA20 이탈

누적거래량
→ 신고가 거래량 조건

최우선매수호가
→ 신규 매수 지정가
```

---

### PullbackTrendStrategy

실제 필요한 값:

```text
현재가
시가
누적거래량
(최우선)매수호가
```

특히 아래 매도 조건 때문에 `시가`가 필요하다.

```text
당일 누적거래량 >= 전일 거래량 × 1.15
AND
현재가 < 시가
```

---

### ValueQualityStrategy

실제 필요한 값:

```text
현재가
(최우선)매수호가
```

현재가는:

```text
-10% 손절
+30% 익절
```

판단에 사용하고,

최우선매수호가는 신규 매수 지정가에 사용한다.

---

# 4. 최종 공통 FID

세 전략의 요구 FID 합집합:

```text
현재가
시가
누적거래량
(최우선)매수호가
```

총 **4개**다.

### 제거된 FID

```text
체결시간
고가
저가
(최우선)매도호가
```

즉:

```text
8개 → 4개
```

로 축소했다.

---

# 5. StrategyManager FID 합집합 구조

각 event-driven 전략에 다음 메서드를 추가하는 구조로 변경했다.

```python
get_required_realtime_fids()
```

예:

```python
def get_required_realtime_fids(self):
    return {
        "현재가",
        "누적거래량",
        "(최우선)매수호가",
    }
```

`StrategyManager`는 각 전략의 FID를 모아 합집합을 만든다.

```text
HighBreakout FID
        +
PullbackTrend FID
        +
ValueQuality FID
        ↓
공통 FID 합집합
```

현재 최종 결과:

```text
현재가
시가
누적거래량
(최우선)매수호가
```

앞으로 새 event-driven 전략을 추가할 때도
그 전략의 `get_required_realtime_fids()`만 정의하면 된다.

---

# 6. HighBreakout 매도 방식 변경

`(최우선)매도호가`를 제거하기 위해
HighBreakout의 매도도 시장가 기준으로 통일했다.

기존:

```text
-5% 손절
→ 시장가

MA20 이탈
→ 최우선매도호가 지정가
```

변경:

```text
-5% 손절
→ 시장가 전량매도

MA20 이탈
→ 시장가 전량매도
```

따라서 신고가 전략에서도
`(최우선)매도호가` 실시간 FID가 필요 없어졌다.

# 7. Kiwoom.py 실시간 콜백 최적화

`SetRealReg` FID만 줄이면
`Kiwoom.py`가 기존처럼 매 틱마다 8개 FID를
`GetCommRealData`로 읽을 수 있기 때문에
콜백 로직도 같이 변경했다.

추가된 개념:

```python
self.stock_realtime_fid_names
```

Manager가 최종 FID 합집합을 계산한 뒤:

```python
set_stock_realtime_fid_names(...)
```

를 통해 Kiwoom에 전달한다.

그 결과 `Kiwoom.py`는
등록된 FID만 실제로 `GetCommRealData`로 읽는다.

현재 기준:

```text
현재가
시가
누적거래량
(최우선)매수호가
```

만 조회한다.

# 11. 아직 하지 않은 최적화

현재는 **1차 최적화**만 적용했다.

```text
8개 공통 FID
    ↓
4개 공통 FID
```

아직 감시용 FID / 주문용 FID 분리는 하지 않았다.

추후 장중 부하가 여전히 크다면:

```text
감시용
현재가
시가
누적거래량
```

과

```text
주문 후보/보유종목
현재가
시가
누적거래량
최우선매수호가
```

처럼 분리하는 2차 최적화를 고려한다.

하지만 우선은 현재 4개 공통 FID 구조의
실제 장중 성능을 먼저 측정한다.
