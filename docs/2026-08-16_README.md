# 2026-08-16 SystemTrading 개발 기록

## 1. 오늘 작업 목표

기존 Kiwoom 자동매매 프로그램에 **웹 모니터링 기능을 추가하기 위한 백엔드 기반**을 구축했다.

오늘 작업의 핵심 목표는 다음과 같다.

- 전략 조건이 발생했지만 실제 주문이 나가지 않은 경우까지 기록
- 전략별 현재 보유종목과 실시간 평가손익을 웹에서 조회
- 전략별 실현/미실현 손익을 시간대별로 저장
- Kiwoom 32bit 프로그램과 웹 서버를 분리
- FastAPI + Swagger를 이용해 React 개발 전에 API를 검증

현재 전체 구조는 다음과 같다.

```text
Kiwoom OpenAPI / StrategyManager
        │
        │  SQLite 저장
        ▼
monitoring.db
strategy_position.db
        │
        │  Read Only
        ▼
FastAPI
        │
        ├─ Swagger (/docs)
        │
        └─ 추후 React Dashboard
```

# 2. 전략 신호 로그 추가

기존에는 실제 주문/체결 결과 중심으로 기록했기 때문에,

> "전략 조건은 만족했는데 왜 주문이 안 나갔는가?"

를 웹에서 확인하기 어려웠다.

이를 해결하기 위해 `monitoring.db`에 다음 테이블을 추가했다.

```text
strategy_signal_log
```

## 저장 내용

주요 컬럼:

```text
signal_id
signal_key
signal_date
strategy_name

code
code_name

signal_type
reason_code
signal_reason

current_price
condition_data

order_attempted
order_result
blocked_reason

first_detected_at
last_detected_at
hit_count
```

## 중복 신호 처리

실시간 틱마다 동일 조건이 반복될 수 있으므로 아래 기준으로 하나의 신호로 묶는다.

```text
strategy_name
+ code
+ date
+ signal_type
+ reason_code
```

같은 신호가 반복되면 새로운 row를 계속 만드는 대신:

```text
hit_count 증가
last_detected_at 갱신
```

방식으로 처리한다.

## 주문 결과

신호가 발생한 뒤 실제 주문 상태를 다음과 같이 구분한다.

```text
ORDER_SENT
BLOCKED
ORDER_FAILED
```

예:

```text
전략 조건 충족
→ BUY Signal 기록

계좌 최대 보유종목 10개 도달
→ 실제 주문 없음

order_result = BLOCKED
blocked_reason = 계좌 최대 보유/대기 10종목 도달
```

# 3. 전략별 신호 코드

## HighBreakoutStrategy

매수:

```text
BREAKOUT_ENTRY
```

매도:

```text
STOP_LOSS
MA20_BREAKDOWN
```

---

## PullbackTrendStrategy

매수:

```text
PULLBACK_ENTRY
```

매도:

```text
STOP_LOSS
MA20_BREAKDOWN
BEARISH_VOLUME
PREVIOUS_HIGH_PARTIAL_EXIT
NEXT_DAY_VOLUME_FADE
```

눌림목의 기존 전고점 관리 로직은 유지했다.

- 전고점 도달 → 30% 부분매도
- 부분매도 주문 성공 후 상태 저장
- 다음 거래일 거래량 감소 → 잔량 전량매도

---

## ValueQualityStrategy

매수:

```text
VALUE_QUALITY_ENTRY
```

매도:

```text
STOP_LOSS
TAKE_PROFIT
```

현재 매도 기준:

```text
-10% 이하 → STOP_LOSS
+30% 이상 → TAKE_PROFIT
```

# 4. Pullback runtime DB 오류 수정

신호 로그용 `db_helper.py`를 교체하는 과정에서 기존 Pullback 전략에서 사용하던 runtime 함수가 빠져 ImportError가 발생했다.

누락됐던 함수:

```text
save_pullback_runtime_state
get_pullback_runtime_state
delete_pullback_runtime_state
```

이를 다시 복구하고 다음 테이블을 추가했다.

```text
pullback_runtime_state
```

현재 VS Code SQLite Viewer에서 다음 테이블 생성까지 확인했다.

```text
strategy_signal_log
pullback_runtime_state
```

# 5. FastAPI 웹 백엔드 구축

Kiwoom 프로그램 안에 웹 서버를 직접 넣지 않고 별도 프로세스로 분리했다.

이유:

- Kiwoom은 Python 32bit + PyQt + ActiveX 환경 필요
- 웹 서버 장애가 자동매매 프로그램에 영향을 주면 안 됨
- FastAPI는 SQLite DB만 읽도록 구성
- 향후 React와 독립적으로 개발 가능

구조:

```text
SystemTrading/
│
├─ main.py
├─ monitoring.db
├─ strategy_position.db
│
├─ run_web_api.py
│
├─ requirements-web.txt
│
└─ web_api/
   ├─ __init__.py
   ├─ main.py
   ├─ database.py
   └─ strategies.py
```


# 8. Python 3.9 FastAPI 타입 힌트 오류 수정

초기 FastAPI 코드에 Python 3.10 문법이 들어가 있었다.

문제 코드:

```python
Literal["BUY", "SELL"] | None
```

Python 3.9에서는 FastAPI/Pydantic이 이를 해석하지 못해 서버 시작이 실패했다.

수정:

```python
Optional[Literal["BUY", "SELL"]]
```

및

```python
Optional[str]
```

형태로 변경했다.

이후 FastAPI 정상 시작 확인:

```text
Started server process
Application startup complete.
```

# 14. 전략 성과 계산 방식

저장 값:

```text
holding_count

open_cost_basis
market_value
unrealized_pnl

cumulative_gross_realized_pnl
cumulative_fee
cumulative_tax
cumulative_net_realized_pnl

total_pnl

lifetime_sold_cost_basis
deployed_capital

return_on_deployed_capital_pct
return_method
```

총손익:

```text
total_pnl
= 누적 순실현손익
+ 현재 미실현손익
```

실제 배치자본:

```text
deployed_capital
= 이미 매도한 수량의 매입원금
+ 현재 보유종목 매입원금
```

수익률:

```text
return_on_deployed_capital_pct
= total_pnl / deployed_capital * 100
```

저장 방식:

```text
return_method = DEPLOYED_CAPITAL_ROI
```

즉 이 수치는:

```text
전략별 독립계좌 NAV 수익률 X
실제 배치 매입원금 대비 누적 손익률 O
```

이다.

오늘 작업을 통해 기존 구조:

```text
Kiwoom 자동매매 프로그램
```

에서 다음 구조로 확장되었다.

```text
Kiwoom 자동매매
       │
       ▼
SQLite 데이터 기록
       │
       ├─ 주문/체결
       ├─ 전략 신호
       ├─ 현재 보유현황
       └─ 전략 성과
       │
       ▼
FastAPI
       │
       ▼
Swagger 검증 완료
       │
       ▼
React Dashboard 개발 준비 완료
```

현재 **웹 프론트엔드를 만들기 위한 백엔드 데이터 구조와 API 기본 골격까지 완료**된 상태다.
