## 2. 적용한 전략과 연결 수정

이번 구현은 Breakout을 먼저 진행하며 Parabolic Long/Short와 EP는 포함하지 않습니다.

- 기존 HighBreakout의 ATR 매수 인자를 수량 산정에 연결했습니다.
- 가상 매도에서 호출하던 `evaluate_sell_signal()` 연결 문제를 수정했습니다.
- 기존 신고가 전략의 웹 MA 설정을 청산 평가에 연결했습니다. ATR 조건을 먼저 검사하고, 기존 MA 수익 청산은 15:19~15:20 구간의 고정 예상 MA를 사용합니다.
- 별도 `MomentumContractionStrategy`를 추가했습니다. 횡보 수축 돌파, 첫 5분 고가 확인, 진입 당시 당일 저가 손절, 부분 매도, 확정 일봉 MA 청산을 가상 계좌에서 평가합니다.
- 동일 초기자금·비용·수량 제한을 사용하는 독립 A/B/C 가상 계좌와 선택적 틱 CSV 기록, 주문 없는 리플레이 도구를 추가했습니다.

| 비교 계좌 | 규칙 |
|---|---|
| A | 기존 180거래일 신고가 전략 |
| B | A에 강한 종목·횡보 수축 후보 필터 추가 |
| C | 별도 모멘텀 수축 돌파 전략 |

C의 기본 설정은 영상의 `C / MINL126` 순위 방식입니다. PDF의 실제 1·3·6개월 수익률 순위 방식은 별도 모드입니다. 상위 2%, 20일 횡보, 선행 상승 30%, TR 수축 70%, 4거래일 후 1/3 부분 매도, MA10 등 구체적인 수치는 구현·비교를 위한 설정이며 국내 시장의 최적값으로 검증하지 않았습니다.

C는 가상 전용입니다. `main.py`의 기존 전략들은 증권사 주문 경로를 유지하므로 프로그램 전체가 가상 전용으로 전환된 것은 아닙니다. 오늘 확인한 계좌 조회는 모의투자였습니다.

## 6. 가상 DB와 틱 CSV 설정

프로젝트 최상위 CMD에서:

```cmd
set "SYSTEMTRADING_PAPER_DB=%CD%\paper_breakout.db"
set "SYSTEMTRADING_PAPER_TICK_CSV=%CD%\ticks\breakout.csv"
py -3.9-32 main.py
```

- `set`은 파일 실행이나 DB 생성 명령이 아니라 해당 CMD의 환경변수 설정입니다. 실제 DB·CSV 쓰기는 프로그램이 수행합니다.
- 같은 CMD에서 실행한 새 프로세스에 적용됩니다. 새 CMD나 이미 실행 중인 프로세스에는 자동 반영되지 않습니다.
- 같은 실험은 고정 DB를 계속 사용해야 현금·포지션·손절선·부분 매도 상태가 이어집니다. 날짜별 새 DB는 새 실험 계좌로 시작합니다.
- 이 환경변수를 지정하지 않으면 기본 가상 저장 위치는 `monitoring.db`입니다. 경로를 바꾸면 기존 가상 기록이 자동 이전되지는 않습니다.
- 웹 API도 동일한 가상 DB 경로로 실행해야 같은 비교 결과를 조회합니다.
- 틱 CSV는 선택 사항입니다. 동일한 파일을 여러 프로그램에서 동시에 기록하지 않습니다.

별도 실행 폴더는 필요 없습니다. 아래 내용을 프로젝트 최상위 `start_trading.bat`에 저장할 수 있습니다.

```bat
@echo off

set "SYSTEMTRADING_PAPER_DB=%CD%\paper_breakout.db"
set "SYSTEMTRADING_PAPER_TICK_CSV=%CD%\ticks\breakout.csv"

```

웹 API는 웹 환경을 활성화한 별도 CMD에서 프로젝트 최상위로 이동한 뒤 실행합니다.

```cmd
set "SYSTEMTRADING_PAPER_DB=%CD%\paper_breakout.db"
python run_web_api.py
```

프론트엔드는 별도 CMD에서:

```cmd

npm run dev
```

접속 주소는 API `http://127.0.0.1:8000`, 웹 `http://localhost:5173/`입니다.

### 다음 작업: 일봉 길이와 최신일 보충

실행 중인 매매 프로그램을 종료한 뒤, 프로젝트 최상위의 64bit 환경에서:

```cmd
conda activate marketdata
python -c "import struct; print(struct.calcsize('P') * 8)"
python bootstrap_market_history.py --lookback-days 540 --overlap-days 540
```

`64` 및 `[공유 DB]`의 실제 프로젝트 `market_history.db` 경로를 확인합니다. 540은 달력일 조회 범위이며 180거래일 자체를 뜻하지 않습니다. 전체시장 수집에는 시간이 걸리고 신규상장 종목은 180봉을 확보하지 못할 수 있습니다.

현재 수집기에서 일봉이 없는 종목은 `--lookback-days`, 이미 있는 종목은 마지막 저장일 이전의 `--overlap-days`로 조회 시작일을 정합니다. 기존 종목의 과거 이력을 늘리려면 두 옵션을 함께 지정해야 합니다.

또한 마지막 저장일이 수집 종료일 이상이면 이력 길이와 관계없이 건너뜁니다. 최신일만 이미 채웠는데 봉수가 부족하다면 이 명령만으로 보충되지 않을 수 있으므로 수집 로그를 확인하고 수집기 수정 여부를 판단해야 합니다. 현재 확인한 DB 최신일은 10월 1일이므로 최신일까지의 보충이 필요한 상태입니다.

수집 후 확인 명령(당시 기준일을 고정한 점검):

```cmd
python -c "import sqlite3; c=sqlite3.connect('file:market_history.db?mode=ro',uri=True); q='SELECT COUNT(*), MIN(n), MAX(n), SUM(n>=127), SUM(n>=180) FROM (SELECT code, COUNT(*) AS n FROM daily_price WHERE date < ? GROUP BY code)'; print('종목수/최소봉수/최대봉수/127봉이상/180봉이상:',c.execute(q,('20261008',)).fetchone()); print('최신 완결일:',c.execute('SELECT MAX(date) FROM daily_price WHERE date < ?',('20261008',)).fetchone()[0]); c.close()"
```

최신일 2026-10-07과 180봉 이상 종목의 존재를 확인한 뒤 `py -3.9-32 main.py`로 재실행합니다. 개별 종목의 결측·가격 유효성 등 추가 조건 때문에 봉수만으로 전략 준비를 보장하지는 않습니다. 이후 날짜에 점검할 때는 `20261008`을 해당 실행일로 바꿉니다.
