# 모멘텀 실제 주문 추가 — 2026-10-08

## 적용 대상과 현재 보유 종목

이미 strategy_cleanup.patch를 적용한 프로젝트에 추가로 적용하는 패치입니다. 기존 정리 패치를 다시 적용하지 마세요.
정리 패치는 매도·취소 주문을 보내지 않았습니다. 기존 신고가·눌림목 보유와 미체결은 증권사 계좌에서 확인하여 수동으로 관리해야 합니다.
종목의 전략 이름을 모멘텀으로 바꾸어 넘기지 마세요. 과거 포지션에 모멘텀 진입 당시의 손절·부분청산 상태가 없기 때문입니다.
수동 매도 후 증권사 잔고와 미체결, 프로그램 재조회 결과를 확인하세요. 프로그램이 꺼져 있으면 체결 이벤트를 받지 못하므로 DB 화면만으로 매도 완료를 판단하지 마세요.

## 변경 후 동작

- ValueQualityStrategy: 기존 증권사 매수·매도 경로 유지.
- MomentumContractionStrategy: 이 코드에서 새로 실제 매수한 보유는 실제 체결 수량과 가격을 기준으로 매도 관리.
- A/B/C: 가상 비교 유지. C의 가상 잔고와 실제 모멘텀 잔고는 별개입니다. 모멘텀 상세 화면의 C 성과·보유는 가상 데이터입니다.
- 제거된 신고가·눌림목: 신규 주문 경로 없음. 과거 보유를 자동으로 모멘텀에 편입하지 않음.

모멘텀은 후보 필터와 첫 구간 돌파 조건을 만족하면 현재 관측 가격의 지정가 매수를 요청합니다.
수량은 기존 계좌 배분·보유 제한과 손절 거리 기반 위험 예산을 함께 적용합니다. 기본 위험 비율은 기존 설정의 0.5%이며, 갭·체결 지연이 있어 실제 손실 상한을 보장하지 않습니다.
손절은 진입 신호의 당일 저가, D+4 이후 수익 상태에서 부분청산, 부분청산 후 본전 비용 보정 및 MA10 청산을 적용합니다. 정확한 조건은 기존 모멘텀 규칙과 동일합니다.
부분청산 완료·손절 상향은 주문 전송 시가 아니라 실제 목표 수량의 체결 후 반영합니다.
사용되는 수수료·세금은 기존 전략 설정의 계산 가정입니다. 계좌에 적용되는 실제 비용과 맞게 설정하세요.

손절은 프로그램이 시세를 받아 매도 주문을 보내는 방식입니다. 증권사에 상시 손절 주문이 미리 저장되는 방식은 아닙니다.
정상 잔고·주문 조회, 유효 시세, 매매 프로세스 실행이 필요합니다.

## 실행

기존 DB 환경변수와 계좌 선택을 그대로 유지합니다. 실제 주문은 로그인한 계좌로 전송됩니다. 모의 로그인이라면 모의 주문입니다.
매매를 실행할 동일한 CMD에서 다음을 실행하세요.

```cmd
set "SYSTEMTRADING_MOMENTUM_LIVE=1"
py -3.9-32 main.py
```

기존 실행 방식이 가상환경 python이라면 동일 환경에서 python main.py를 쓰세요. 시작 로그의 모멘텀 신규매수 활성 메시지를 확인합니다.
환경변수는 해당 CMD와 그 자식 프로세스에 적용되며, 이미 실행 중인 프로세스에는 소급 적용되지 않습니다.
우량주는 기존 규칙을 만족할 때 주문하며 이 변수로 켜거나 끄지 않습니다.

모멘텀 신규매수를 끄려면 매매 프로세스를 종료하고 다음처럼 재실행하세요.

```cmd
set "SYSTEMTRADING_MOMENTUM_LIVE=0"
py -3.9-32 main.py
```

이 경우 신규 모멘텀 매수만 중지하며, 이 코드로 매수한 모멘텀 기존 보유의 매도 관리는 계속합니다.

## DB와 재시작

시장 이력 DB와 같은 디렉터리에 momentum_live.db를 생성합니다. 손절 가격, 실제 체결 수량, 부분청산 진행, 대기 주문 및 중복 체결 방지 기록을 계좌별로 저장합니다.
monitoring.db의 체결 로그와 함께 재시작 시 복원합니다. 두 DB를 같이 보존하세요. C용 paper DB는 별도로 유지합니다.
손절 상태가 없거나 실제 잔고와 수량이 맞지 않으면 임의의 손절값을 만들어 매도하지 않고 경고 후 관리를 보류합니다.
주문 접수 여부가 불명확하거나 접수 번호가 복구되지 않은 대기 상태는 자동 재주문하지 않습니다. 증권사 미체결·체결 기록과 상태를 확인해야 합니다.
같은 날 같은 종목의 반복 진입도 기록으로 차단합니다.
실보유 중 이 패치를 되돌리면 모멘텀 자동 관리가 중단되므로 보유 관리 방법을 먼저 정해야 합니다.
