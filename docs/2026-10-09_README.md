## 1. 목적과 확인된 진행 상태

우량주와 모멘텀을 중심으로 프로젝트를 정리하고, A/B/C 가상 비교는 유지하기로 했습니다.
발표에서는 기존 전략 비교와 구성 단순화 과정을 설명할 수 있습니다. 다만 이번 코드 정리·테스트만으로 모멘텀이 다른 전략보다 수익성이 우수하다고 입증한 것은 아닙니다. 성과 비교에는 저장한 동일 기간·비용 가정의 데이터가 필요합니다.

| 작업 | 이번 대화에서 확인한 상태 |
|---|---|
| 기존 전략 화면 보존 | 사용자가 웹 화면을 PDF로 저장했다고 설명 |
| 삭제 전 코드 보존 | 사용자가 백업 브랜치에 저장했다고 설명; 원격 푸시 여부는 확인하지 않음 |

| Qullamaggie 링크 | 추가 패치·전체 변경 코드를 제공하고 빌드·적용 검사 완료; 사용자 PC 화면 확인은 아직 없음 |

## 3. A/B/C 유지와 비교 기준

| 계좌 | 후보·진입 차이 | 청산 |
|---|---|---|
| A | 기존 180거래일 신고가 기준 | ATR 및 장 마감 전 MA 수익 청산 |
| B | A에 모멘텀 후보 필터 추가 | A와 동일 |
| C | 모멘텀 후보·수축·첫 구간 고가 돌파 | 당일 저가 손절, D+4 수익 부분청산, 확정 종가 MA10 |

A와 B는 후보 필터 차이를, B와 C는 서로 다른 진입·청산 방식의 결과를 관찰하는 데 사용할 수 있습니다. B와 C는 여러 규칙이 동시에 다르므로 성과 차이를 특정 한 조건의 효과로 단정하지 않습니다.
A/B MA 설정은 모멘텀 상세 화면으로 이동하고 다음 거래일 적용 정책을 유지합니다. C의 MA 설정과 별개입니다.
웹 설정 경로는 `/api/strategies/MomentumContractionStrategy/ma-settings`입니다. 과거 신고가 상세/설정 경로는 제거됩니다.

A/B는 180거래일 이력, C는 최소 127봉과 기준일 최신 일봉이 필요합니다. CSV 리플레이는 기존처럼 C만 재현합니다.

## 4. 기존 실제 보유·미체결 관리

정리 패치를 적용하는 행위는 주식을 매도하거나 주문을 취소하지 않습니다.
신고가·눌림목 실행 클래스를 제거하면 해당 전략의 기존 보유를 자동으로 매도하는 경로도 중단됩니다.
사용자는 기존 보유를 수동 관리하기로 했으며, 매도 완료 여부는 이번 대화에서 확인하지 않았습니다.

- 증권사 실제 잔고와 미체결을 확인합니다.
- 수동 매도·취소 후 프로그램의 정상 잔고/주문 재조회 결과를 확인합니다.
- 프로그램이 꺼져 있으면 체결 이벤트를 받지 못하므로 DB 표시만으로 완료를 판단하지 않습니다.
- 과거 포지션의 전략 이름만 모멘텀으로 바꾸지 않습니다. 진입 당시의 손절·부분청산 상태가 없는 포지션을 새 전략이 자동으로 인수하지 않습니다.

## 5. 모멘텀 실제 주문 경로 추가

새 파일 `strategy/LiveMomentumContractionStrategy.py`가 기존 모멘텀 후보·진입·청산 규칙을 재사용합니다.
가상 C는 유지하고 실제 주문은 별도 어댑터로 실행합니다. 우량주의 기존 증권사 주문 경로는 유지합니다.

| 항목 | 동작 |
|---|---|
| 실제 신규매수 | 환경변수 값이 정확히 1일 때 활성화 |
| 실제 매수 방식 | 현재 관측 가격의 지정가 매수 요청 |
| 수량 | 공용 계좌 배분·보유 제한과 손절 거리 기반 위험 수량 제한 함께 적용 |
| 초기 손절 | 진입 신호의 당일 저가를 주문 전에 저장 |
| 부분청산 | 기본 D+4 이후 비용 가정 반영 수익 상태에서 초기 실제 체결 수량 약 1/3 |
| 부분청산 상태 갱신 | 목표 수량이 실제 체결된 뒤 완료 및 본전 손절 상향 반영 |
| 잔여 청산 | 부분청산 이후 기본 MA10 확정 종가 하회; 1주 보유는 D+4 이후 MA 조건 |
| 신규매수 비활성화 | 새 매수만 중지; 이 코드로 매수한 기존 모멘텀 보유의 매도 관리는 유지 |
| 주문 취소 | 손절 발생 시 기존 대기 주문의 취소 확인을 기다린 뒤 잔여 보유 관리 |

`StrategyManager`는 미등록·가상 전용 전략의 실제 매수 요청을 막습니다. 실제 모멘텀에는 손절·위험 인자가 필요합니다.
기본 위험 비율 0.5%와 비용 값은 전략 설정의 계획·계산 가정입니다. 실제 손실 한도나 현재 계좌의 정확한 비용을 보장하지 않습니다.

### 실행 방법

이미 전략 정리 패치를 적용한 코드에 `momentum_live.patch`를 추가 적용한 다음, 동일한 매매 CMD에서 실행합니다.

```cmd
set "SYSTEMTRADING_MOMENTUM_LIVE=1"
py -3.9-32 main.py
```

기존 Kiwoom 가상환경으로 실행한다면 동일 환경의 `python main.py`를 사용합니다.

```text
[Momentum] 증권사 신규매수 활성
```

환경변수는 이미 실행 중인 프로세스에 소급 적용되지 않습니다. 연결 계좌가 실제 계좌인지 모의 계좌인지는 Kiwoom 로그인·계좌 선택에 따릅니다.
신규 모멘텀 매수를 끄려면 매매 프로그램을 종료한 뒤 다음처럼 재실행합니다.

```cmd
set "SYSTEMTRADING_MOMENTUM_LIVE=0"
py -3.9-32 main.py
```

우량주 주문은 이 변수로 제어하지 않습니다. 자동 손절은 실행 중인 프로그램이 주문하는 방식이며 증권사 상시 손절 주문으로 저장되는 구조가 아닙니다.

## 6. 실제 상태 저장과 복구

시장 이력 DB와 같은 디렉터리의 `momentum_live.db`에 계좌별 상태를 저장합니다.

- 실제 체결 평균 가격·수량과 초기 수량
- 초기/현재 손절 가격
- 부분청산 목표·체결 진행 및 완료 상태
- 대기 주문, 주문 번호, 당일 재진입 차단 날짜
- 중복 체결 방지 기록

공통 `monitoring.db` 체결 로그를 재반영하여 중간 종료 시 상태 복구를 지원합니다. 두 DB를 함께 보존합니다.
잔고와 체결 상태가 불일치하거나 손절 상태가 없으면 임의로 손절값을 생성하지 않고 관리를 보류합니다.
접수 여부가 불명확한 주문은 자동 재주문하지 않습니다. 증권사 체결·미체결과 저장 상태를 확인해야 합니다.
기존 가상 비교는 같은 `SYSTEMTRADING_PAPER_DB`를 매매·웹 프로세스에서 지정하여 계속 사용합니다.
