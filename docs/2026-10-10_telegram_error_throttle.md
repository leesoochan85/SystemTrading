# 2026-10-10 텔레그램 반복 오류 제한

기준: GitHub main 커밋 `68b3f2609ff5fcf869b95e520757e425012a31ca` 및 앞서 제공한 경로 숨김 수정본.

## 동작

| 상황 | 텔레그램 | CMD |
|---|---|---|
| 오류 최초 발생 | 즉시 전송 시도 | 원문 기록 |
| 같은 오류가 10분 안에 재발 | 전송 생략 | 매번 원문 기록 |
| 10분 경과 후 같은 오류 재발 | 재전송 시도, 생략한 반복 횟수 표시 | 원문 기록 |
| 다른 오류·종목·전략·채팅방 | 별도 제한 상태로 처리 | 원문 기록 |
| 매수·매도·체결·취소 완료, /status, /help | 기존 전송 방식 | 기존 방식 |

재알림은 10분 뒤 자동 예약되는 것이 아니라, 10분이 지난 후 해당 오류가 다시 발생할 때 실행된다.
실패한 전송 시도도 제한에 포함한다. 텔레그램 장애가 지속될 때 매 틱마다 HTTP 요청을 반복하지 않기 위함이다.
오류 필터는 매매 판단·주문 재시도·계좌 안전 중지 조건을 변경하지 않는다.

## 수정 파일

- `util/notifier.py`: `send_error()` 및 공통 제한 상태 추가. 기존 텔레그램 경로 숨김 유지.
- `api/Kiwoom.py`: 예수금·미체결·잔고 조회 예외를 오류 전용 함수로 전송.
- `strategy/StrategyManager.py`: 초기화·매수 요청·취소 실패·포지션 후처리·장마감 갱신·step 예외 및 예수금 안전 중지에 적용.
- `strategy/ValueQualityStrategy.py`: 초기화 오류 및 매도 주문 전송 실패에 적용.
- 테스트용 notifier 대역에 `send_error()` 추가. 제한 전용 테스트와 Manager 통합 테스트 추가.

오류는 발생 함수와 메시지로 구분한다. Traceback은 머리말·중복 제거한 호출 위치·마지막 예외 문장으로 비교한다.
같은 예외 객체가 다시 던져져 Traceback이 길어지는 경우도 반복으로 처리한다.
매도·취소 주문 전송 실패는 종목과 반환 오류 코드로 구분하여 가격·수익률 변화로 제한을 우회하지 않게 한다.

## 제한과 적용 범위

- `ERROR_REPEAT_INTERVAL_SECONDS = 600`을 수정하면 간격을 변경할 수 있다. 단위는 초이며 양수를 사용한다.
- 상태는 프로세스 메모리에 저장된다. 프로그램 재시작 시 초기화되어 첫 오류를 다시 전송한다.
- 상태는 최대 512개다. 초과 시 최근 사용하지 않은 항목부터 제거하며 제거된 오류가 재발하면 처음처럼 전송할 수 있다.
- 서로 다른 오류가 많이 발생하는 경우 전체 알림 수를 제한하는 기능은 아니다.
- 텍스트 자체가 달라지는 일반 오류는 별도 오류로 처리할 수 있다.
- Kiwoom 조회 예외와 Manager 안전 중지는 별도 알림이다. 최초 장애에서 두 알림이 함께 나올 수 있다.
- 미체결·잔고 조회 안전 중지와 복구는 기존 상태 변화 기반 알림을 유지한다.
- 일봉 저장률 경고·DB 불일치·초기화 완료·리포트·주문/체결 단계별 알림의 통합은 이번 범위에 포함하지 않는다.
- 제한을 적용해도 오류 원인을 해결하는 것은 아니다. 원문 Traceback으로 원인을 확인해야 한다.

## 검증

- 경로 숨김 및 반복 제한 테스트 17개 통과.
- Manager `step()` 반복 오류, 예수금 안전 중지 통합 테스트 2개 통과.
- 전략 테스트 포함 총 85개 통과. 외부 요청을 실패시키는 대역을 사용해 네트워크 및 실주문 없이 실행.
- 실행 환경에 requests가 없어 전체 전략 검증에서 HTTP 모듈을 대역으로 공급했다. 알림 전용 테스트는 원래부터 가짜 HTTP 응답으로 검증한다.
- FastAPI 미설치로 기존 웹 API 테스트 2개는 미실행. Windows·키움·실제 텔레그램 수신 환경은 미검증.
- Python 3.9 문법 검사 및 패치 적용·결과 파일 일치 검증 완료.

## 적용

1. 프로그램을 종료한다.
2. 프로젝트 폴더에서 `git status`로 현재 변경 사항을 확인하고 필요한 변경을 백업한다.
3. 아래 두 패치 중 현재 상태에 맞는 **하나만** 프로젝트 최상위에 넣는다.

| 현재 코드 | 사용할 패치 |
|---|---|
| 앞서 제공한 경로 숨김 패치를 적용한 상태 | `telegram_error_throttle_after_privacy.patch` |
| 위 기준 main 상태이며 경로 숨김 미적용 | `telegram_error_throttle_from_main.patch` |

경로 숨김 적용 상태:

```bat
git apply --check telegram_error_throttle_after_privacy.patch
git apply telegram_error_throttle_after_privacy.patch
```

경로 숨김 미적용 main 상태:

```bat
git apply --check telegram_error_throttle_from_main.patch
git apply telegram_error_throttle_from_main.patch
```

명령은 하나씩 실행하고, `--check`가 성공했을 때만 적용 명령을 실행한다.
패치 검사에 실패하면 현재 파일과 기준 코드가 다르다는 뜻이므로 강제 적용하거나 전체 파일로 덮어쓰지 않는다.
`source/` 폴더에는 비교를 위한 최종 수정 파일이 들어 있다.

4. 적용 후 다음 명령으로 알림 테스트를 실행한다.

```bat
python -m unittest discover -s tests -p "test_notifier*.py" -v
```

5. 프로그램을 다시 실행한다. 테스트는 실제 텔레그램 메시지나 주문을 보내지 않는다.

GitHub 및 사용자 PC에는 자동 반영하지 않았다.
