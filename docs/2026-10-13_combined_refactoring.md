## 유지되는 것

- 모멘텀 매수·매도 조건, 위험 예산·보유 한도·비용 설정 및 실제 주문 활성화 방식.
- `MomentumContractionStrategy` 내부 계좌 식별자와 DB 스키마.
- 기존 모멘텀 현금·보유수량·손절선·부분매도·거래·수익률·MDD 이력.
- 과거 A/B DB 행: 삭제·합산·초기화하지 않으며 추가 거래/갱신/조회에서 제외.
- A/B 과거 기록이 보존되고 신규 주문되지 않는지 확인하는 회귀 테스트.
- 기존 `/paper-account` 조회와 `/paper-comparison` 호환 경로.
- 기존 `strategy_settings.db`와 과거 상태 DB 파일: 코드 정리 과정에서 삭제하지 않음.
- 공개 웹 조회 함수 21개와 조회 응답 형식, 기간 필터·페이지 조회·성과 계산.
- 우량주 리포트의 30분 검사·한 번에 최대 1건 전송·성공 결과 기록·콘솔 오류 제한.
- 기존 리포트 조회 커서 전진 정책. 리포트 전송 대기열을 새로 만든 변경은 아님.
- 실행 BAT와 사용 중인 DB 경로.

A/B 문자열은 과거 기록을 다루는 테스트와 역사 문서에 남을 수 있다.
과거 기록 검증용 식별자는 현재 운영 프로필을 뜻하지 않는다.
Wilder ATR은 이름과 파일 위치를 바꾸었으며 수학적 계산과 결정일 이전 봉 사용 기준은 유지했다.
일봉 수집기의 기본 180봉 목표도 유지한다.

## 검증

- 기준 main 테스트: 164개 통과.
- 통합 수정본 Python unittest: 175개 통과.
- 기존 공개 조회 함수 서명 21개·조회 결과 사례 12개 일치.
- 공용 ATR 검증 7개를 변경 전 계산 코드에도 적용하여 동일한 기대 결과 확인.
- 기존 C 부분매도·손절·잔고·재진입 차단과 기존 A/B 행 보존 검증 유지.
- 리포트 검증 시나리오 6개를 기존 Manager 코드에도 적용하여 같은 기대 결과 확인.
- 프론트엔드 프로덕션 빌드 성공 및 폴링 테스트 4개 통과.
- Python 컴파일·3.9 문법 검사와 정확한 기준 소스에 대한 패치 적용 검증.

이 환경에서는 실제 Windows Kiwoom ActiveX 로그인·장중 주문·Telegram 전송을 실행하지 않았다.
사용자 PC에서 테스트 후 기존 BAT로 재시작한다.

## 적용

매매 프로그램과 웹 API를 종료하고 프로젝트 루트에서 실행한다.

```cmd
git apply --check combined_refactoring.patch
git apply combined_refactoring.patch
run_tests.bat
cd web_frontend
npm run build
npm test
```

기존 DB를 유지한다. 이후 기존 BAT와 프론트엔드 실행 방법으로 재시작하고
브라우저를 새로고침한다. DB 초기화·재무/일봉 재수집은 이 패치를 적용하는 데 필요하지 않다.
패치 검사 실패 시 강제 초기화하지 말고 사용자 PC의 변경과 기준 소스를 비교한다.
원격 GitHub에는 push하지 않았다.
