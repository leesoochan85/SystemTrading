# 2026-10-15 우량주 주문·모멘텀 웹 가상매매 병행 확인

기준: GitHub main `84a90a5` (재무 수집·TTM·Windows 연결 종료 패치 포함).

## 확인한 기존 흐름

`main.py`가 우량주와 `LiveMomentumContractionStrategy`를 Manager에 전달한다. `VirtualStrategyEngine` 안의 `MomentumPaperEngine`도 같은 모멘텀 객체를 참조한다. Manager는 가상 엔진과 실제 전략 리스너를 같은 Kiwoom 실시간 이벤트에 연결한다. 따라서 기존에도 웹 가상매매는 증권사 신규매수 허용 여부·예수금·보유 한도와 독립적으로 실행된다.

`[Momentum] 신규매수 중지`는 증권사 신규주문의 설정이며 가상계좌 중지가 아니다. 신규 가상매수는 가상계좌 자체의 현금·위험·보유 한도를 따른다. 실제 주문이 모의계좌인지 실계좌인지는 Kiwoom 로그인에 따라 달라진다.

## 수집과 후보의 차이

1. `update_market_data.bat` 1/2: 종목별 일봉 OHLCV와 종목 마스터를 저장.
2. `start_trading.bat`: 최신 기준일에 맞는 최소 127개 일봉·ATR이 있는 종목의 지표 계산.
3. 순위와 전략 필터를 모두 통과한 종목만 후보로 선정.
4. 후보가 실시간 첫 구간 고가·횡보 고가 돌파와 ATR 손절 폭 조건을 만족하면 가상 진입.

현재 설정은 126거래일 최저가 대비 상승 지표 상위 2%, ADR(20)>3.5%, 20일 평균 거래대금 20억원 이상, 선행 60거래일 구간의 상승 30% 이상, 20일 횡보 중 최근 5일 TR/앞선 15일 TR≤0.7, 최근 5일 저점≥앞선 5일 저점이다. 이는 프로젝트 설정에 구현된 실험적 판정 기준이다. 데이터가 없다는 뜻과 후보가 없다는 뜻을 구분한다.

사용자 로그의 `0/2524`는 유효 이력 2,524개 중 모든 조건을 통과한 종목이 0개라는 뜻이다. 어느 조건에서 모두 제외됐는지는 이 한 줄로 확정할 수 없다. 새 로그가 단계별 통과 수를 출력하며 웹에도 기존 단계별 통과 수를 유지한다.

## 수정

- 시작 로그가 우량주 증권사 주문·모멘텀 가상계좌 병행과 증권사 신규매수 설정을 구분한다.
- 혼동을 주던 `가상 전용 후보` 문구를 `공통 신호 후보`로 변경하고 필터별 통과 수를 출력한다.
- 기존에는 가상 틱/체결로 dirty 상태가 된 경우에만 스냅샷을 기록했다. 후보·체결이 0개여도 초기 평가액과 heartbeat를 기록하도록 바꿨다.
- 기존 5초 저장 제한을 유지한다. 장외에는 Manager의 기존 주기/강제 저장 시점에 기록한다.
- 상태는 기존 `paper_run_status.stats_json`의 `paper_execution`에 기록한다. 기존 API의 최상위 응답 키와 호출 인자는 유지한다. 테이블 삭제·계좌 초기화는 하지 않는다.
- 웹에서 후보 없음·실시간 신호 대기·첫 구간 누락·장 전/후·갱신 실패, 최근 상태·유효 틱 시각, 모멘텀 증권사 신규매수 설정을 구분한다. 장중 30초 이상 상태가 갱신되지 않으면 지연으로 표시한다.
- 평가액은 마지막 관측 가격으로 계산한다. heartbeat는 전체 보유 종목의 최신 시세를 보증하지 않는다.

## 실행

패치 후 `run_tests.bat`을 실행하고 `web_frontend`에서 `npm test`, `npm run build`를 확인한다. 이후 기존 `start_trading.bat`과 별도 CMD의 `start_web_api.bat`을 실행한다. 두 BAT는 동일 프로젝트의 `paper_breakout.db`를 사용한다. 기존 DB와 거래 기록을 유지한다.

`start_web_api.bat`은 현재 React 개발 서버도 함께 실행한다. 웹을 이미 켜두었다면 코드 반영을 위해 필요한 프로세스만 재시작한다. 새로운 재무 전체 수집이나 가상 DB 초기화는 이 패치 적용에 필요하지 않다.

정상적인 신규 모멘텀 진입 검증은 다음 거래일 장 시작 전에 실행해 첫 구간부터 관측해야 한다. 후보가 0개인 날의 거래 0건은 정상일 수 있다. 늦게 실행한 날의 첫 구간을 당일 고가로 대체하거나 가상 체결을 임의로 만들지 않는다.

## 검증

- Python 자동 테스트 207개 통과: 증권사 모멘텀 신규매수 설정이 켜져 있어도 실제 계좌가 10종목·예수금 0원·주문 guard 차단이면 실제 모멘텀 주문 없이 가상 매수·매도가 진행됨을 확인.
- 우량주 실제 주문 처리 함수와 모멘텀 가상체결이 같은 실행 안에서 각각 호출됨을 합성 틱·가상 브로커로 검증.
- 후보 0개 상태의 초기 평가액·heartbeat·웹 조회, 5초 저장 제한, 늦은 시작 시 신규매수 차단 검증.
- 프론트엔드 테스트 7개 통과와 Vite 빌드 성공. 한국시간 heartbeat·갱신 지연·장외/첫 구간 미관측 표시 검증.

실제 사용자 PC의 Kiwoom 틱 수신·주문·웹 화면은 이 개발 환경에서 확인하지 않았다. 다음 실행 로그와 웹 상태로 최종 확인한다.
