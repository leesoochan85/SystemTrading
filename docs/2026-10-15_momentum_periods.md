# 1·3·6개월 수익률별 독립 가상매매 비교

## 계산과 비교 범위

원문: https://qullamaggie.com/my-3-timeless-setups-that-have-made-me-tens-of-millions/

원문은 1·3·6개월 상승률 상위 1~2%를 스캔하도록 안내한다. 이 구현은 기간별 성과를 비교하기 위한 프로젝트 실험이다. 월을 21·63·126거래일로 환산하는 방식, 아래 수치 필터와 자동 판정식은 프로젝트의 구현 기준이다.

| 가상계좌 | 순위 지표 | 모드 |
|---|---|---|
| 1개월 | (최근 확정 종가 / 21거래일 전 종가 - 1) × 100 | return_21 |
| 3개월 | (최근 확정 종가 / 63거래일 전 종가 - 1) × 100 | return_63 |
| 6개월 | (최근 확정 종가 / 126거래일 전 종가 - 1) × 100 | return_126 |

각 기간별로 따로 순위를 매긴다. 합집합 하나로 매매하거나 세 기간 모두 통과하도록 요구하지 않는다. 같은 종목이 여러 기간에 선정되면 계좌별 독립 진입·청산·당일 재진입 차단을 적용한다. 기존 126일 최저가 대비 상승 계좌와 과거 기록은 유지하며 기간 비교 계좌에 합산하지 않는다.

세 계좌는 동일한 완료 일봉 집합을 재사용한다. 기본 설정에서 최신 기준일 일봉과 최소 127봉이 있는 기업 주식만 대상으로 하므로, 짧은 기간 계좌에만 신규 상장 종목이 포함되지 않는다. 장중 당일 일봉이나 장중 현재가로 상승률 순위를 다시 매기지 않는다. 다음 기준일에 공통 자료를 갱신한다. 원래 일봉 조회를 세 번 반복하지 않는다.

## 같은 조건

순위는 공통 유효 종목 집합 전체에서 먼저 계산한다. 기본값은 기간별 상위 2%이며 `ceil(유효 종목 수 × 0.02)`개를 선정한다. 동률은 종목코드 오름차순으로 처리한다. 다음 조건에서 탈락했다고 다음 순위 종목을 보충하지 않는다.

1. ADR(20) > 3.5%.
2. 최근 20일 평균 거래대금(종가×거래량 근사) ≥ 20억원.
3. 횡보 20일에 앞선 60일 구간의 마지막 종가 / 그 구간 최저 종가 - 1 ≥ 30%.
4. 횡보 20일의 최근 5일 평균 TR / 앞선 15일 평균 TR ≤ 0.7.
5. 최근 5일 최저가 ≥ 앞선 5일 최저가.
6. 첫 5분 고가와 횡보 고가를 모두 돌파하고, 당일 저가까지 손절 거리가 ATR 한도 이내면 진입.

수치 설정은 공통 `config/momentum_contraction.json`에서 복사하며 기간 모드만 바꾼다. 초기자금 기본 1천만원, 위험 비율, 종목 비중·보유 한도, 수수료·세금·슬리피지, 당일 저가 손절·부분청산·MA 청산도 같다. 실제 계좌 현금이나 보유 수가 세 가상계좌의 진입을 막지 않는다. 실제 주문 API에는 비교 계좌를 연결하지 않는다.

## 저장과 실행

`start_trading.bat`과 `start_web_api.bat`의 기존 사용법을 따른다. 코드 반영 후 두 프로세스를 재시작한다. 일봉이 이미 최신이라면 기간 비교를 위해 재무 전체 수집을 다시 할 필요는 없다.

기존 `SYSTEMTRADING_PAPER_DB` 경로의 파일명을 기준으로 세 DB를 만든다. 예를 들어 기존 `paper_breakout.db` 옆에 다음 파일이 생긴다.

- paper_breakout_momentum_1m_v1.db
- paper_breakout_momentum_3m_v1.db
- paper_breakout_momentum_6m_v1.db

웹 API와 매매 프로세스는 같은 기본 DB 경로를 사용해야 한다. 재시작하면 계좌별 현금·보유·체결·당일 진입 이력을 복원한다. 기존 DB를 지우거나 초기화하지 않는다. 이미 시작한 실험의 설정을 바꾸면 기존 PaperBroker의 설정 변경 차단이 작동한다. 비교 조건을 바꿀 때는 별도 기본 DB 경로로 새 실험을 시작하고 기존 기록을 보존한다.

세 기간의 최종 후보와 열린 가상 보유 종목을 공통 실시간 등록에 포함한다. 기존 계좌 후보가 0개여도 다른 기간의 후보는 감시한다. 모든 후보가 0개여도 초기 평가액·상태는 기록하며 신규 진입을 기다린다. 틱 CSV 기록은 후보/보유의 합집합을 한 번만 기록한다.

장 시작 전 등록부터 첫 5분 체결을 관측해야 한다. 장중 실행·체결 누락 시 기존의 진입 보류 규칙을 유지한다. 과거 당일 고가로 누락 구간을 채우지 않는다. 계좌별 오류는 다른 계좌의 틱 처리·상태 저장을 건너뛰게 하지 않는다.

## 웹 확인

모멘텀 페이지 상단에서 세 계좌의 비용 차감 수익률·관측 MDD·완료 거래 수·승률·이익합/손실합·후보 수·실행 상태를 비교한다. 상세 계좌 선택에서 각 기간 또는 기존 계좌를 고르면 아래의 단계별 통과 수·후보와 진입 상태·보유·체결 내역이 바뀐다.

추가 조회 API: `GET /api/strategies/MomentumContractionStrategy/momentum-periods`. 기존 `paper-account` 응답은 기존 계좌를 그대로 반환한다. 조회는 계좌 DB를 생성하거나 변경하지 않는다. 계좌 생성시각·자금/전략 조건·기준 일봉이 다르면 웹에서 주의를 표시하며, 누락된 관측일을 0%로 만들지 않는다.

성과는 적용 후 받은 틱으로 쌓이는 전진 검증이다. 일봉만으로 과거 장중 체결 성과를 만들지 않는다. MDD는 5초 스냅샷에서 관측한 평가액 기준이며 실제 계좌 성과와 다를 수 있다. 수익률만 보지 말고 완료 거래 수·관측 기간·낙폭을 함께 비교한다.

## 검증

Python 테스트 223개, 프론트엔드 테스트 9개와 Vite 빌드를 통과했다. 기간별로 다른 순위, 필터 적용 순서, 공통 이력 1회 조회, 같은 종목의 독립 체결, 현금 분리, 재시작·재진입 차단, 기간 전용 후보의 실시간 등록, 후보 탈락 후 손절, 후보 0개 상태 기록, 장중 시작 차단, 읽기 전용 API와 차트 누락일을 검증했다. Kiwoom 접속·실제 사용자 PC에서의 장중 수신은 이 개발 환경에서 검증하지 않았다.
