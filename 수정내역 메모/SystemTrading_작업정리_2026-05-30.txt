SystemTrading 자동매매 프로그램 작업 정리
작성일: 2026-05-30 (토)
대상 프로젝트: SystemTrading / Kiwoom OpenAPI 자동매매

============================================================
1. 오늘 작업의 목표
============================================================

오늘의 핵심 목표는 새로운 매수 전략을 추가하는 것이 아니라,
실전 자동매매 중 발생할 수 있는 주문·DB 불일치를 줄이는 것이었다.

구체적으로는 아래 상황을 안정적으로 처리하도록 개선했다.

1) 매수 주문이 장시간 체결되지 않고 남아 있는 경우
2) 일부 수량만 체결되고 나머지 수량이 계속 미체결인 경우
3) 보유 종목을 전량 매도한 뒤 전략 DB 기록이 남아 있는 경우
4) 장 마감 직전에 신규 매수 주문이 들어가 취소 처리가 애매해지는 경우
5) 키움 응답의 종목코드 형식(A005930 / 005930)이 달라 주문 추적이 끊기는 경우
6) 장중 계좌 조회가 너무 자주 실행되어 OpenAPI 요청 제한 위험이 생기는 경우


============================================================
2. 최종적으로 반영된 주요 기능
============================================================

[1] 주문 접수 시 전략 포지션 DB 저장 방식 유지
------------------------------------------------------------
현재 방식대로 매수 주문 접수 성공 시점에 position_strategy DB에
해당 종목과 매수 전략명을 저장하도록 유지했다.

이 방식을 유지한 이유:
- 체결 완료 시점에만 DB를 기록하려면 주문과 전략을 별도로 기억할 구조가 필요함
- 아직 pending_order 전용 DB를 만들지 않았으므로, 현재 방식이 전략 추적에는 더 안전함

대상:
- RSIStrategy
- HighBreakoutStrategy
- BandTrendStrategy
- BandReversionStrategy


[2] 매수 주문에 주문 시각(order_time) 저장
------------------------------------------------------------
각 전략에서 매수 주문이 정상 접수되면 self.kiwoom.order[code]에
order_time = time.time() 값을 저장하도록 반영했다.

목적:
- 최초 주문 시점부터 10분이 지났는지 판단하기 위함


[3] 매수 미체결 주문 10분 후 자동취소
------------------------------------------------------------
StrategyManager에 매수 미체결 주문 자동취소 로직을 추가했다.

동작:
- 매수 주문만 대상으로 확인
- 미체결수량이 0보다 큰 경우만 확인
- 최초 매수 주문 후 600초(10분)가 지나면 취소 주문 전송
- 취소 수량은 전체 주문수량이 아니라 현재 남아 있는 미체결수량

예시:
- 100주 매수 주문
- 30주 체결, 70주 미체결
- 10분 경과
- 남은 70주만 자동취소 요청


[4] 동일 매수취소 주문 반복 전송 방지
------------------------------------------------------------
StrategyManager에 아래 상태 관리값을 추가했다.

- pending_buy_cancellations = {}

이미 취소 요청을 보낸 종목은 취소 처리가 확인되기 전까지
같은 취소 주문을 반복해서 보내지 않도록 처리했다.


[5] 전량 미체결 취소 완료 후 position_strategy DB 삭제
------------------------------------------------------------
매수취소 주문을 보냈다고 바로 DB를 삭제하지 않도록 수정했다.

현재 처리 방식:
- 취소 요청 후 미체결 목록에서 종목이 사라졌는지 확인
- 실제 잔고에도 해당 종목이 없는지 확인
- 조회 반영 지연 가능성을 고려하여 위 상태를 2회 연속 확인
- 전량 미체결 취소가 확정되면 position_strategy DB에서 삭제

이 방식으로 방지되는 문제:
- 취소 처리 직전 일부 수량이 체결됐는데 DB를 먼저 삭제해버리는 문제


[6] 일부 체결 후 잔량 취소 시 position_strategy DB 유지
------------------------------------------------------------
매수 주문 일부가 체결된 상태에서 남은 수량만 취소된 경우,
실제 잔고에 종목이 있으므로 position_strategy DB 기록을 유지한다.

예시:
- 100주 주문
- 30주 체결
- 70주 자동취소 완료
- 30주는 실제 보유 종목이므로 해당 전략명이 DB에 남아 있어야 함


[7] 전량 매도 완료 시 position_strategy DB 삭제
------------------------------------------------------------
Kiwoom의 체결 이벤트 처리에서 실제 전량 매도 체결이 확인된 경우에만
position_strategy DB에서 해당 종목 기록을 삭제하도록 보완했다.

최종 조건:
- 주문구분이 정확히 "매도"
- 체결량이 0보다 큼
- 미체결수량이 0

중요한 보완:
- "매도취소" 문자열에도 "매도"가 포함되므로,
  단순히 "매도" 포함 여부만으로 삭제하지 않도록 수정함
- 따라서 매도 주문을 취소했는데 실제 보유 중인 종목의 전략 DB가
  삭제되는 위험을 줄였다.


[8] 종목코드 형식 통일
------------------------------------------------------------
키움 OpenAPI 응답에서 종목코드가 A005930 형태로 들어올 수 있고,
전략 내부에서는 005930 형태로 저장하므로 key 불일치 가능성이 있었다.

현재 Kiwoom.py에서 아래 세 경로 모두 종목코드를 6자리로 통일했다.

- 미체결 주문 조회
- 잔고 조회
- 체결 이벤트 수신

처리 방식:
- 앞에 A가 있으면 제거
- zfill(6)으로 6자리 문자열 유지

결과:
- 주문 기록 key: 005930
- 미체결 조회 key: 005930
- 잔고 조회 key: 005930
- 체결 이벤트 key: 005930

이 수정으로 order_time, strategy_name, 잔고, 체결 이벤트가
같은 종목코드 기준으로 연결될 수 있게 됐다.


[9] 장중 미체결·잔고 조회량 축소
------------------------------------------------------------
장중 1초마다 미체결 주문과 잔고를 조회하면 키움 OpenAPI 요청 제한에
걸릴 위험이 있으므로 조회 주기를 줄였다.

현재 설정:
- 전략 검사: 1초마다 종목 1개 검사
- 미체결 주문 조회: 장중 60초마다
- 잔고 조회: 장중 60초마다
- 예수금 동기화: 5분마다
- 장외 주문·잔고 상태 점검: 5분마다

관련 설정:
- order_sync_interval = 60
- deposit_sync_interval = 300
- market_closed_interval = 300000


[10] 장 마감 직전 신규 매수 제한
------------------------------------------------------------
장 마감 직전 매수 주문이 들어가면 10분 자동취소 시점이
장 종료 이후로 넘어갈 수 있으므로 신규 매수 제한을 추가했다.

현재 동작:
- 15:15 이전: 신규 매수 가능
- 15:15 ~ 15:30: 신규 매수 차단

적용 전략:
- RSIStrategy
- HighBreakoutStrategy
- BandTrendStrategy
- BandReversionStrategy


[11] RSI 전략의 예상 매수비용 비율 통일
------------------------------------------------------------
RSI 전략의 예상 매수금액 계산값을 다른 전략과 동일하게 맞췄다.

현재:
- estimated_amount = math.floor(amount * 1.00035)

즉, 전략별 매수 비용 계산 기준이 동일해졌다.

============================================================
4. 현재 자동매매 동작 흐름
============================================================

[매수 흐름]
1) 각 전략이 매수 조건 확인
2) 15:15 이후이면 신규 매수 중단
3) 보유 종목 및 기존 미체결 주문 여부 확인
4) 주문 접수 성공 시:
   - 예수금 예상 차감
   - position_strategy DB에 전략 저장
   - order_time 기록
   - 텔레그램 매수 알림

[매수 미체결 관리 흐름]
1) StrategyManager가 장중 60초마다 미체결·잔고 조회
2) 매수 주문 잔량이 남아 있고 최초 주문 후 10분 경과 여부 확인
3) 경과 시 남아 있는 잔량만 매수취소 주문
4) 동일 주문은 다시 취소하지 않음
5) 이후 조회 결과:
   - 잔고 있음: 일부 체결로 판단, 전략 DB 유지
   - 잔고 없음 + 미체결 목록에서도 사라짐: 2회 확인 후 전략 DB 삭제

[매도 흐름]
1) 보유 종목의 매수 전략명을 position_strategy DB에서 조회
2) 해당 전략만 매도 조건 검사
3) 실제 전량 매도 체결 확인 시 position_strategy DB 삭제

5. 오늘 발생한 문법 검사 명령어 오류와 해결
============================================================

실행한 명령:
python -m py_compile api\Kiwoom.py strategy\StrategyManager.py ...

발생한 오류:
FileNotFoundError: No such file or directory: 'apiKiwoom.py'

원인:
- 현재 터미널은 Git Bash(MINGW64)
- Git Bash에서는 역슬래시(\)가 Windows 경로 구분자가 아니라
  이스케이프 문자로 처리됨
- 따라서 api\Kiwoom.py가 apiKiwoom.py로 해석됨

Git Bash에서 사용할 올바른 명령어:

python -m py_compile api/Kiwoom.py strategy/StrategyManager.py strategy/RSIStrategy.py strategy/BandTrendStrategy.py strategy/BandReversionStrategy.py strategy/HighBreakoutStrategy.py util/time_helper.py && echo "문법 검사 성공"

참고:
- Windows CMD 또는 PowerShell에서는 역슬래시 경로도 사용 가능
- Git Bash에서는 슬래시(/) 경로를 사용하는 것이 안전함

9. 현재 단계 최종 평가
============================================================

오늘 작업 결과, 자동매매 프로그램은 단순히 매수·매도 조건을 검사하는 수준에서
다음과 같은 실전 운영 안전장치를 갖춘 상태로 발전했다.

- 매수 미체결 방치 방지
- 부분체결 잔량 자동 정리
- 전략 DB와 실제 보유 상태 불일치 위험 감소
- 전량 매도 후 DB 정리
- 장 마감 임박 신규 매수 차단
- 키움 종목코드 불일치 문제 해결
- 과도한 장중 계좌조회 완화

현재는 기능 추가보다 실제 장중 검증이 필요한 단계다.
다음 거래일에 모의투자 또는 최소 수량으로 주문/취소/체결/DB 삭제 흐름을
순서대로 확인한 뒤, 재시작 복구 기능과 추가 리스크 제한 기능으로 넘어가는 것이 적절하다.
